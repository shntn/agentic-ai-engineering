# プロンプトチェイニング — ブログ組立ライン

タスクを固定された一連のステップに分解し、各LLM呼び出しが前のステップの出力を処理します。シンプルで、線形的で、予測可能です——それでいて、個々のステップは根拠のある出力のためにWeb検索のようなツールを使うこともできます。

## 🎯 学べること

- ステージ間で明確な引き継ぎを持つ、複数ステップのLLMパイプラインを設計する
- 焦点を絞ったプロンプトを使って、連続する呼び出しの間でコンテキストと結果を受け渡す
- ステップごとのコールバックとトークン追跡で、チェーン全体の実行をデバッグ・トレースする
- チェイニングが単一の複雑なプロンプトに勝るのはどんなときかを知る

## 🔑 キーコンセプト

### 連続したパイプライン

```mermaid
---
config:
  look: handDrawn
  theme: neutral
---
flowchart LR
    A["🗣️ トピック     "] -->|request| B["🧠 Outliner / Sonnet     "]
    B -->|outline| C["🧠 Writer / Haiku + 🔍     "]
    C -->|draft| D["🧠 Editor / Sonnet     "]
    D -->|polished| E["📄 完成した記事     "]
```

各ステップは焦点を絞ったシステムプロンプトと単一の責務を持ちます。あるステップの出力が、次のステップの入力になります。

### 品質ゲート

ステップとステップの間で、前のステップが使用可能な出力を生成したかを検証します。アウトライナーが空のテキストを返した場合、下流にゴミを送るのではなく早期に中止します。

### デュアルモデル戦略

このチェーンでは、タスクの複雑さに応じてステップごとに異なるモデルを使用します:

- **Sonnet**（ステップ1と3）: アウトライン作成と編集にはニュアンスと判断力が必要
- **Haiku**（ステップ2）: 構造化されたアウトラインからの執筆はより単純明快——高速で安価なモデルで十分機能する

これは実践的なコスト最適化です: 最も高性能なモデルは、それが重要な場面でのみ使います。

### チェーン内でのWeb検索

ステップ2（Writer）は、Anthropicの組み込みWeb検索ツールにアクセスでき、1回の実行あたり3回まで使用に制限されています:

```python
WEB_SEARCH_TOOL = {"type": "web_search_20250305", "name": "web_search", "max_uses": 3}
```

モデルは検索するかどうかを自律的に判断します——システムプロンプトには「トピックが最新の情報から恩恵を受ける場合はWeb検索を使用する」と書かれています。これにより、チェーンをシンプルに保ちながら（明示的な検索ロジックなしに）、根拠のある最新のコンテンツを実現できます。

### ステップ設計

- **Outliner**（Sonnet）: 構造（タイトル + 5個の箇条書き）を生成する
- **Writer**（Haiku + Web検索）: アウトラインを完全なブログ記事に展開する。各セクション2〜3段落
- **Editor**（Sonnet）: 文法・明瞭さ・流れを磨き上げる。Key Takeawaysセクションを追加する

各プロンプトはそれぞれの特定のタスクに最適化されています——「何でもこなす」単一のプロンプトではありません。

### チェイニング vs 単一プロンプト、どちらを選ぶか

チェイニングは複雑さを増します——恩恵がコストを上回る場合に使用しましょう:

- **チェイニングを選ぶ場合**: 各ステップの要件が異なる（モデル、ツール、temperature）、中間出力に検証が必要、あるいはデバッグに各ステージへの可視性が求められる場合
- **単一プロンプトを選ぶ場合**: タスクが十分にシンプルで、1つのよく練られたプロンプトで確実に処理できる場合——ステップを追加することはレイテンシと失敗ポイントを増やすだけです

このチュートリアルではチェイニングが有効です。なぜなら各ステップが本当に異なるセットアップの恩恵を受けるからです: アウトライナーには精度が必要（Sonnet）、ライターにはWebアクセスが必要（Haiku + 検索）、エディターには判断力が必要（Sonnet）。

## ⚠️ 重要な考慮事項

- チェーンの長さが重要です——各ステップがレイテンシとトークンコストを増やします
- エラーは複合します: ライタープロンプトがどれだけ優れていても、悪いアウトラインからは悪い記事しか生まれません
- Web検索はレイテンシと非決定性を増やします——同じトピックでも検索結果によって異なる記事が生成される可能性があります
- 本番利用では、ステップ間に検証/ゲートを追加することを検討してください
